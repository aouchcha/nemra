# Nemra Backend

Spring Boot REST API for a service marketplace platform. The codebase is organized as a modular monolith with authentication, users, providers, categories, jobs, reviews, and shared infrastructure.

## Tech Stack

- Java 21
- Spring Boot 3.3.x
- Spring Web
- Spring Security
- Spring Data JPA
- PostgreSQL
- Flyway
- JWT
- Cloudflare R2 via AWS SDK S3 client
- Apache Tika

## Architecture

The project follows a layered backend structure:

- `controller` handles HTTP routes.
- `service` contains business logic.
- `repository` handles persistence.
- `model` contains JPA entities.
- `dto` contains request/response payloads.
- `shared` contains utilities, wrappers, and exceptions.

`MapperToDTO.java` is the shared mapping layer used to convert entities into API DTOs.

## Security Model

`SecurityConfig` uses stateless JWT authentication.

- Public:
  - `POST /api/auth/register/**`
  - `POST /api/auth/login`
- Authenticated:
  - all other routes unless a controller adds role restrictions
- Role-restricted:
  - category writes require `ADMIN`
  - job creation requires `CLIENT`
  - job acceptance and completion require `PROVIDER`
  - provider profile update requires `PROVIDER`

## API Endpoints

All non-list responses are wrapped in `ApiResponse` with the shape:

```json
{
  "message": "string",
  "data": {},
  "success": true
}
```

### Auth

| Method | Route | Request DTO | Response DTO |
|---|---|---|---|
| `POST` | `/api/auth/register/client` | `RegisterClient` -> `RegisterRequest` fields: `fullName`, `phoneNumber`, `password`, `city` | `AuthResponse` |
| `POST` | `/api/auth/register/provider` | `RegisterProvider` -> `RegisterRequest` fields plus `business_name`, `category`, `bio`, `years_of_experience`, `avatar` | `AuthResponse` |
| `POST` | `/api/auth/login` | `LoginRequest` with `number`, `password` | `AuthResponse` |
| `POST` | `/api/auth/refresh-token` | No body, `Authorization` header | `AuthResponse` |
| `POST` | `/api/auth/logout` | No body, `Authorization` header | No `data` payload |

### Users

| Method | Route | Request DTO | Response DTO |
|---|---|---|---|
| `GET` | `/api/users/me` | None | `UserDTO` |
| `PUT` | `/api/users/me` | `RegisterRequest` with `fullName`, `phoneNumber`, `password`, `city` | `UserDTO` |

### Providers

| Method | Route | Request DTO | Response DTO |
|---|---|---|---|
| `GET` | `/api/providers` | None | `ProviderSummaryDTO` list |
| `GET` | `/api/providers/{user_id}` | None | `ProviderDTO` |
| `PUT` | `/api/providers/me` | `RegisterProvider` | `ProviderDTO` |
| `GET` | `/api/providers/{provider_id}/reviews` | None | `ReviewResponseDTO` list |

### Categories

| Method | Route | Request DTO | Response DTO |
|---|---|---|---|
| `GET` | `/api/categories` | None | `CategoryDTO` list returned raw, not wrapped |
| `POST` | `/api/categories` | `CreateCategoryRequest` with `nameAr`, `nameFr`, `nameEn` | No `data` payload |
| `PUT` | `/api/categories/{category_id}` | `CreateCategoryRequest` with `nameAr`, `nameFr`, `nameEn` | No `data` payload |
| `DELETE` | `/api/categories/{category_id}` | None | No `data` payload |

### Jobs

| Method | Route | Request DTO | Response DTO |
|---|---|---|---|
| `POST` | `/api/jobs` | `CreateJobRequest` with `description` | `JobPendingDTO` at creation time |
| `GET` | `/api/jobs/my` | None | `JobPendingDTO` list, with runtime variants `JobCompletedDTO` and `JobNotCompletedDTO` |
| `GET` | `/api/jobs/{job_id}` | None | `JobPendingDTO` base type, with runtime variants based on status |
| `PATCH` | `/api/jobs/{job_id}/accept` | None | `JobPendingDTO` / `JobNotCompletedDTO` depending job state |
| `PATCH` | `/api/jobs/{job_id}/complete` | None | `JobCompletedDTO` |
| `PATCH` | `/api/jobs/{job_id}/cancel` | None | `JobPendingDTO` / `JobNotCompletedDTO` depending job state |

### Reviews

| Method | Route | Request DTO | Response DTO |
|---|---|---|---|
| `POST` | `/api/reviews` | `CreateReviewDTO` with `jobId`, `reviewedId`, `reviewerType`, `comment`, and rating fields | `ReviewResponseDTO` |
| `GET` | `/api/reviews/provider/{id}` | None | `ProviderReviewDTO` list |
| `GET` | `/api/reviews/client/{id}` | None | `ClientReviewDTO` list |

## MapperToDTO.java

`src/main/java/backend/nemra/shared/utils/MapperToDTO.java` centralizes entity-to-DTO conversion.

Current mappings:

- `ProviderProfile` -> `ProviderDTO`
- `ProviderProfile` -> `ProviderSummaryDTO`
- `ClientProfile` -> `ClientProfileDTO`
- `User` -> `UserDTO`
- `Category` -> `CategoryDTO`
- `Review` -> `ReviewResponseDTO`
- `Review` -> `ClientReviewDTO`
- `Review` -> `ProviderReviewDTO`
- `Job` -> `JobPendingDTO`, `JobNotCompletedDTO`, or `JobCompletedDTO` depending on status

## Notes

- `ClientController.java` currently has no endpoints.
- `SecurityConfig` permits `/api/uploads/**`, but there is no controller for it in the current tree.
- `AuthResponse` includes `accessToken`, `refreshToken`, and `user`.
